# Аудит параметров: Cube Orange + ELRS + Walksnail

## Система
- **Автопилот:** Cube Orange
- **Прошивка:** ArduPilot Copter
- **RC:** ExpressLRS (CRSF)
- **Видео/OSD:** Walksnail Avatar V2 Dual Kit (MSP DisplayPort)

---

## ЧАСТЬ 1: ИСПРАВЛЕНИЕ RSSI / LQ НА OSD

### Причина проблемы

В param-файле стояло:

```
RSSI_TYPE    = 2   ← берёт RSSI из RC-канала (PWM)
RSSI_CHANNEL = 15  ← указывает на канал 15
```

**ExpressLRS НЕ передаёт RSSI через RC-каналы.**
ELRS передаёт RSSI и LQ через пакеты CRSF Link Statistics.

Поэтому OSD показывал мусор или фиксированные значения вместо реальных данных.

### Исправление (2 параметра)

| Параметр | Было | Стало | Почему |
|----------|------|-------|--------|
| `RSSI_TYPE` | 2 | **3** | 3 = ReceiverProtocol — берёт данные из CRSF телеметрии |
| `RSSI_CHANNEL` | 15 | **0** | 0 = не используется (RSSI идёт из протокола, а не из канала) |

### Что будет отображаться на OSD после исправления

| Элемент OSD | Что показывает | Значения |
|-------------|----------------|----------|
| `RSSI` (OSD1_RSSI_EN=1) | Link Quality (LQ) в процентах | 0–100% |
| `LinkQ` (OSD1_LINK_Q_EN=1) | Link Quality (LQ) в процентах | 0–100% |
| `RSSI dBm` | Мощность сигнала в dBm (если поддерживается) | −130...0 dBm |

> **Важно:** В ArduPilot при RSSI_TYPE=3 значение RSSI% = LQ. Это нормальное поведение для ELRS.

### Нормальные значения ELRS

| Качество связи | LQ (RSSI на OSD) | RSSI dBm |
|----------------|------------------|----------|
| Отличное | 95–100% | > −80 dBm |
| Хорошее | 70–95% | −80...−100 dBm |
| Слабое | 40–70% | −100...−110 dBm |
| Критическое | < 30% | < −110 dBm |
| Failsafe | 0% | нет сигнала |

## ЧАСТЬ 2: ЧТО УЖЕ НАСТРОЕНО ПРАВИЛЬНО

| Параметр | Значение | Назначение | Статус |
|----------|----------|------------|--------|
| `SERIAL4_PROTOCOL` | 23 | CRSF (RCIN) для ELRS | ✅ Правильно |
| `SERIAL4_BAUD` | 115 | Baud rate (420K включается через RC_OPTIONS бит 13) | ✅ Правильно |
| `RC_PROTOCOLS` | 512 | CRSF протокол | ✅ Правильно |
| `RC_OPTIONS` | 8708 | ELRS suppress + 420K baud + failsafe ignore | ✅ Правильно |
| `OSD_TYPE` | 5 | MSP DisplayPort (Walksnail) | ✅ Правильно |
| `SERIAL2_PROTOCOL` | 42 | MSP DisplayPort для Walksnail | ✅ Правильно |
| `SERIAL2_BAUD` | 115 | 115200 для MSP | ✅ Правильно |
| `OSD1_RSSI_EN` | 1 | RSSI на OSD включён | ✅ Правильно |
| `OSD1_LINK_Q_EN` | 1 | LQ на OSD включён | ✅ Правильно |
| `RC_SPEED` | 490 | ESC PWM частота | ✅ Правильно |
| `TELEM_DELAY` | 0 | Без задержки телеметрии | ✅ Правильно |

### Расшифровка RC_OPTIONS = 8708

```
8708 = 8192 + 512 + 4

Бит 2  (4)    = Ignore receiver failsafe bit
Бит 9  (512)  = Suppress CRSF mode/rate message for ELRS
Бит 13 (8192) = Use 420K baud rate for ELRS ← КЛЮЧЕВОЙ
```

Именно **бит 13 (значение 8192)** включает 420K baud для ELRS автоматически, поэтому `SERIAL4_BAUD = 115` — это правильная настройка. Менять на 420 **не нужно**.

Источник: [expresslrs.org/quick-start/ardupilot-setup](https://expresslrs.org/quick-start/ardupilot-setup/)

## ЧАСТЬ 3: UART BAUD RATE ELRS RX (460800 vs 420000)

Вы упоминали, что в TX и RX стоит скорость **460800**.

### TX модуль (460800)
TX модуль общается с **радио** (EdgeTX/OpenTX), а не с автопилотом.
460800 для TX — **не влияет** на ArduPilot.

### RX приёмник (460800) — нужно исправить
RX приёмник общается с **Cube Orange** через UART.
CRSF протокол стандартно работает на **420000** baud.

ArduPilot (через RC_OPTIONS бит 13) ожидает именно **420000** baud.

Разница между 460800 и 420000 составляет **~9.7%** — это выходит за пределы нормальной UART толерантности (~3-5%).

**Последствия mismatch:**
- нестабильный RSSI
- скачки LQ
- потеря пакетов
- occasional jitter стиков

### Как исправить
1. Подключитесь к WiFi точке доступа ELRS приёмника
2. Откройте ELRS Web UI
3. Найдите параметр **UART Baud**
4. Установите **420000**
5. Сохраните и перезагрузите приёмник

## ЧАСТЬ 4: ЗАДЕРЖКА УПРАВЛЕНИЯ (LATENCY)

### Источники задержки в системе

| Источник | Типичная задержка | Можно ли уменьшить |
|----------|------------------|--------------------|
| ELRS Packet Rate (зависит от настройки) | 4–20 мс | Да — увеличить Packet Rate |
| CRSF serial передача | ~2 мс | Нет |
| ArduPilot обработка RC | ~2.5 мс (при 400 Гц) | Нет (400 Гц достаточно) |
| PID контроллер | ~2.5 мс | Нет |
| ESC PWM output (при 490 Гц) | ~2 мс | Да — перейти на DShot |
| **ATC_INPUT_TC (сглаживание входа)** | **до 150 мс!** | **Да — уменьшить** |
| IOMCU (если моторы на MAIN выходах) | ~2.5 мс | Да — использовать AUX |

### Скрытый параметр: ATC_INPUT_TC

Это самый важный параметр для задержки управления, который почти никто не проверяет.

`ATC_INPUT_TC` — Attitude Control Input Time Constant (постоянная времени сглаживания входа управления).

- **По умолчанию: 0.15 секунд (150 мс!)**
- Все команды стиков проходят через фильтр с этой постоянной времени
- Для отзывчивого управления это может быть слишком много

**Рекомендации:**

| Стиль полёта | ATC_INPUT_TC | Эффект |
|-------------|-------------|--------|
| Стабильный / аэросъёмка | 0.15–0.20 | Плавные движения, медленная реакция |
| Обычный полёт | 0.10 | Баланс между плавностью и откликом |
| FPV / быстрый полёт | 0.05 | Быстрая реакция, чуть дёрганее |
| Минимальная задержка | 0.03 | Максимальный отклик |

**Проверьте значение ATC_INPUT_TC в вашем param-файле.** Если оно 0.15 или выше — это главный источник "тупости" стиков.

### IOMCU на Cube Orange

На Cube Orange есть два набора выходов:
- **MAIN OUT (1-8)** — через IO-процессор (IOMCU) — добавляет ~2.5 мс задержки
- **AUX OUT (1-6)** — напрямую от FMU — без дополнительной задержки

Если моторы подключены к MAIN OUT — есть дополнительная задержка. Перенос моторов на AUX OUT уменьшит latency (требует переназначение SERVO функций).

### DShot вместо PWM

Если ваши ESC поддерживают DShot (BLHeli_S / BLHeli_32 / AM32):

| Протокол | Задержка | Параметр |
|---------|---------|---------|
| PWM 490 Гц | ~2 мс | MOT_PWM_TYPE = 0 |
| DShot150 | ~100 мкс | MOT_PWM_TYPE = 4 |
| DShot300 | ~50 мкс | MOT_PWM_TYPE = 5 |
| DShot600 | ~25 мкс | MOT_PWM_TYPE = 6 |

DShot также обеспечивает двунаправленную телеметрию ESC (RPM, температура).

## ЧАСТЬ 5: ОПТИМАЛЬНЫЕ НАСТРОЙКИ ELRS ДЛЯ ДАЛЬНИХ ПОЛЁТОВ

### Настройки ELRS TX Module (Lua Script)

| Параметр | Рекомендация | Почему |
|----------|-------------|--------|
| **Packet Rate** | 150 Гц | Баланс задержки (~16 мс) и дальности |
| **Telemetry Ratio** | 1:32 | Минимальное влияние на задержку стиков |
| **Switch Mode** | Hybrid | Оптимум для автопилотов |
| **RF Mode** | Dynamic | Авто-переключение для максимальной дальности |
| **Model Match** | OFF | Предотвращает проблемы с failsafe на автопилотах |
| **Dynamic Power** | ON | Автоматическая регулировка мощности |

### Packet Rate vs дальность vs задержка

| Packet Rate | Задержка | Дальность (относительно) | Использование |
|------------|---------|------------------------|-------------|
| 50 Гц | ~40 мс | Максимальная | Дальние полёты 100+ км |
| 100 Гц | ~25 мс | Очень большая | Дальние полёты 50–100 км |
| 150 Гц | ~16 мс | Большая | Дальние полёты 20–50 км |
| 250 Гц | ~8 мс | Средняя | FPV полёты до 20 км |
| 500 Гц | ~4 мс | Малая | FPV гонки |

## ФИНАЛЬНЫЙ СПИСОК ИЗМЕНЕНИЙ

### В ArduPilot (Mission Planner)

| # | Параметр | Было | Стало | Приоритет |
|---|----------|------|-------|----------|
| 1 | `RSSI_TYPE` | 2 | **3** | КРИТИЧНО |
| 2 | `RSSI_CHANNEL` | 15 | **0** | КРИТИЧНО |

**Это всё, что нужно изменить в ArduPilot для исправления RSSI/LQ на OSD.**

### В ELRS приёмнике (Web UI)

| # | Параметр | Было | Стало | Приоритет |
|---|----------|------|-------|----------|
| 3 | UART Baud (RX) | 460800 | **420000** | ВАЖНО |

### Для уменьшения задержки (опционально)

| # | Параметр | Действие | Эффект |
|---|----------|---------|--------|
| 4 | `ATC_INPUT_TC` | Уменьшить до 0.05–0.10 | −50...−100 мс задержки стиков |
| 5 | `MOT_PWM_TYPE` | Если ESC поддерживает DShot → 4/5/6 | Уменьшение задержки ESC |
| 6 | ELRS Packet Rate | 150 Гц | Задержка ~16 мс |
| 7 | ELRS Telemetry Ratio | 1:32 | Минимальное влияние на стики |

### НЕ МЕНЯТЬ (распространённые ошибочные советы)

| Параметр | Значение | Почему НЕ менять |
|----------|---------|-----------------|
| `SERIAL4_BAUD` | 115 | RC_OPTIONS бит 13 уже включает 420K baud |
| `RC_SPEED` | 490 | Это ESC PWM частота, не ELRS |
| `RC_OPTIONS` | 8708 | Уже правильно настроен для ELRS |
| `SCHED_LOOP_RATE` | 400 | Стандартное безопасное значение, 800 может перегрузить CPU |

## ПОРЯДОК ДЕЙСТВИЙ

1. **Mission Planner → Config → Full Parameter List:**
   - `RSSI_TYPE` → **3**
   - `RSSI_CHANNEL` → **0**
   - Нажать "Write Params"

2. **ELRS Web UI (приёмник):**
   - UART Baud → **420000**
   - Сохранить и перезагрузить приёмник

3. **Перезагрузить автопилот** (отключить и подключить питание)

4. **Включить аппаратуру**

5. **Проверить в Mission Planner → Status:**
   - `rssi` — должен меняться при изменении расстояния / условий
   - На OSD Walksnail — должны показываться реальные LQ и RSSI

6. **Опционально:** Проверить `ATC_INPUT_TC` — если хотите уменьшить задержку стиков
