# Глубокий аудит параметров: Cube Orange + ELRS + Walksnail

## Система
- **Автопилот:** Cube Orange
- **Прошивка:** ArduPilot Copter
- **RC:** ExpressLRS (CRSF)
- **Видео/OSD:** Walksnail Avatar V2 Dual Kit (MSP DisplayPort)

---

## ЧАСТЬ 1: ИСПРАВЛЕНИЕ RSSI / LQ НА OSD

### Причина проблемы

В param-файле:

```
RSSI_TYPE = 2       ← берёт RSSI из RC-канала (PWM)
RSSI_CHANNEL = 15   ← указывает канал 15
```

**ExpressLRS НЕ передаёт RSSI через RC-каналы.**
ELRS передаёт RSSI и LQ через пакеты CRSF Link Statistics.

Поэтому OSD показывает мусор или фиксированные значения.

### Исправление (2 параметра)

| Параметр | Было | Стало | Почему |
|----------|------|-------|--------|
| `RSSI_TYPE` | 2 | **3** | 3 = ReceiverProtocol — берёт данные из CRSF телеметрии |
| `RSSI_CHANNEL` | 15 | **0** | 0 = не используется (RSSI идёт из протокола, а не из канала) |

### Что будет отображаться на OSD после исправления

| Элемент OSD | Что показывает | Значения |
|-------------|---------------|----------|
| `RSSI` (OSD1_RSSI_EN=1) | Link Quality (LQ) в процентах | 0–100% |
| `LinkQ` (OSD1_LINK_Q_EN=1) | Link Quality (LQ) в процентах | 0–100% |
| `RSSI dBm` | Мощность сигнала в dBm | -130...0 dBm |

> **Важно:** В ArduPilot при RSSI_TYPE=3 значение RSSI% = LQ. Это нормальное поведение.
> Реальный RSSI dBm доступен как отдельный элемент OSD (если поддерживается прошивкой).

### Нормальные значения ELRS

| Качество связи | LQ (RSSI на OSD) | RSSI dBm |
|---------------|-------------------|----------|
| Отличное | 95–100% | > -80 dBm |
| Хорошее | 70–95% | -80...-100 dBm |
| Слабое | 40–70% | -100...-110 dBm |
| Критическое | < 30% | < -110 dBm |
| Failsafe | 0% | нет сигнала |

## ЧАСТЬ 2: ИСПРАВЛЕНИЕ ОШИБОК ИЗ ПРЕДЫДУЩЕГО АНАЛИЗА

> **ВНИМАНИЕ:** Предыдущий анализ в чате содержал несколько ошибок. Ниже — корректная информация, основанная на официальной документации ArduPilot и ExpressLRS.

### Ошибка 1: "SERIAL4_BAUD = 115 — неправильно, надо 420"

**Это НЕВЕРНО.** `SERIAL4_BAUD = 115` — это правильная настройка в вашей конфигурации.

**Причина:** В вашем файле `RC_OPTIONS = 8708`. Разберём побитно:

```
8708 = 8192 + 512 + 4

Бит 2  (4)    = Ignore receiver failsafe bit
Бит 9  (512)  = Suppress CRSF mode/rate message for ELRS
Бит 13 (8192) = Use 420K baud rate for ELRS
```

**Бит 13 (значение 8192) включает 420K baud для ELRS автоматически**, независимо от значения `SERIAL4_BAUD`. Это официальный способ настройки по документации ExpressLRS:

> *"Set SERIALx_BAUD = 115. Enable Bit 13 of RC_OPTIONS for 420K baud rate."*
> — [expresslrs.org/quick-start/ardupilot-setup](https://expresslrs.org/quick-start/ardupilot-setup)

**Менять SERIAL4_BAUD на 420 НЕ нужно.** Текущая настройка работает правильно.

### Ошибка 2: "RC_SPEED = 490 — неправильно, надо 0"

**Это НЕВЕРНО.** `RC_SPEED` — это частота обновления ШИМ-выходов на ESC (регуляторы моторов).

- `RC_SPEED = 490` означает 490 Гц PWM на выходах моторов
- Это **НЕ связано с ELRS** вообще
- ELRS входная частота управляется протоколом CRSF и Packet Rate
- 490 Гц — стандартное значение для PWM ESC

**Менять RC_SPEED НЕ нужно** (если только вы не переходите на DShot).

### Ошибка 3: "RC_OPTIONS надо поменять на 768"

**Это НЕВЕРНО.** `RC_OPTIONS = 8708` — уже правильно настроен для ELRS:

- Бит 9 (512) — подавление предупреждений CRSF rate mismatch
- Бит 13 (8192) — включение 420K baud для ELRS

**Менять RC_OPTIONS НЕ нужно.**

### Ошибка 4: "SCHED_LOOP_RATE надо поставить 800"

**Это РИСКОВАННО.** `SCHED_LOOP_RATE = 400` — стандартное значение для ArduCopter.

- Разница между 400 Гц и 800 Гц = ~1.25 мс (микросекунды, не миллисекунды)
- Это пренебрежимо мало по сравнению с другими источниками задержки
- Установка 800 Гц может вызвать перегрузку CPU и нестабильность
- ArduPilot официально не рекомендует менять это значение без тщательного тестирования

**Менять SCHED_LOOP_RATE НЕ рекомендуется.**

## ЧАСТЬ 4: ЗАДЕРЖКА УПРАВЛЕНИЯ (LATENCY)

### Источники задержки в вашей системе

| Источник | Типичная задержка | Можно ли уменьшить |
|----------|------------------|-------------------|
| ELRS Packet Rate (зависит от настройки) | 4–20 мс | Да — увеличить Packet Rate |
| CRSF serial передача | ~2 мс | Нет |
| ArduPilot обработка RC | ~2.5 мс (при 400 Гц) | Нет (400 Гц достаточно) |
| PID контроллер | ~2.5 мс | Нет |
| ESC PWM output (при 490 Гц) | ~2 мс | Да — перейти на DShot |
| **ATC_INPUT_TC (сглаживание входа)** | **до 150 мс!** | **Да — уменьшить** |
| IOMCU (если моторы на MAIN выходах) | ~2.5 мс | Да — использовать AUX |

### Скрытый параметр: ATC_INPUT_TC

**Это самый важный параметр для задержки управления, который почти никто не проверяет.**

`ATC_INPUT_TC` — Attitude Control Input Time Constant (постоянная времени сглаживания входа управления).

- **По умолчанию: 0.15 секунд (150 мс!)**
- Это значит, что все команды стиков проходят через фильтр с постоянной 150 мс
- Для отзывчивого управления (FPV стиль) это слишком много

**Рекомендации:**

| Стиль полёта | ATC_INPUT_TC | Эффект |
|-------------|-------------|--------|
| Стабильный/аэросъёмка | 0.15–0.20 | Плавные движения, медленная реакция |
| Обычный полёт | 0.10 | Баланс между плавностью и откликом |
| FPV / быстрый полёт | 0.05 | Быстрая реакция, но дёрганее |
| Минимальная задержка | 0.03 | Максимальный отклик |

**Проверьте значение ATC_INPUT_TC в вашем param-файле.** Если оно 0.15 или выше — это главный источник "тупости" стиков.

### IOMCU на Cube Orange

На Cube Orange есть два набора выходов:
- **MAIN OUT (1-8)** — через IO-процессор (IOMCU) — добавляет ~2.5 мс задержки
- **AUX OUT (1-6)** — напрямую от FMU — без дополнительной задержки

Если моторы подключены к MAIN OUT — есть дополнительная задержка. Перенос моторов на AUX OUT уменьшит latency (требует переназначение SERVO функций).

### DShot вместо PWM

Если ваши ESC поддерживают DShot (BLHeli_S / BLHeli_32 / AM32):

| Протокол | Задержка | Параметр |
|---------|---------|---------|
| PWM 490 Гц | ~2 мс | MOT_PWM_TYPE = 0 |
| DShot150 | ~100 мкс | MOT_PWM_TYPE = 4 |
| DShot300 | ~50 мкс | MOT_PWM_TYPE = 5 |
| DShot600 | ~25 мкс | MOT_PWM_TYPE = 6 |

DShot также обеспечивает двунаправленную телеметрию ESC (RPM, температура).

## ЧАСТЬ 5: ELRS RX UART BAUD RATE (460800 vs 420000)

Вы написали, что в TX и RX стоит скорость **460800**.

### TX модуль (460800)
TX модуль общается с **радио** (EdgeTX/OpenTX), а не с автопилотом.
460800 для TX — **не влияет** на ArduPilot.

### RX приёмник (460800)
RX приёмник общается с **Cube Orange** через UART.
CRSF протокол стандартно работает на **420000** baud.

ArduPilot (через RC_OPTIONS бит 13) ожидает **420000** baud.

**Если ELRS RX настроен на 460800, а ArduPilot ожидает 420000 — возможен mismatch.**

Хотя UART может работать с небольшой разницей baud rate (толерантность ~3-5%), разница между 420000 и 460800 составляет **~9.7%**, что выходит за пределы нормальной толерантности.

### Рекомендация

**Установите UART baud rate в ELRS RX на 420000** (стандартное значение):

1. Откройте ELRS Web UI (подключитесь к WiFi точке доступа приёмника)
2. Найдите параметр **UART Baud**
3. Установите **420000**
4. Сохраните и перезагрузите приёмник

## ЧАСТЬ 7: ПОТЕРЯ ТЕЛЕМЕТРИИ

### Причины потери телеметрии ELRS → ArduPilot → OSD

1. **RSSI_TYPE = 2** (ваш случай) — ArduPilot ищет RSSI в RC канале, а не в CRSF пакетах
2. **Baud rate mismatch** (460800 vs 420000) — может вызывать потерю пакетов
3. **Telemetry Ratio слишком высокий** (1:2 или 1:4) — забирает bandwidth у стиков
4. **MAVLink перегрузка** — слишком высокие SR параметры для радио-канала

### Проверка телеметрии

После исправления параметров откройте Mission Planner → Status и проверьте:

| Поле | Должно быть |
|------|------------|
| `rssi` | Меняется при движении (0-255) |
| `remrssi` | Меняется |
| Вкладка Messages | Нет ошибок CRSF |

## ЧАСТЬ 9: ПОРЯДОК ДЕЙСТВИЙ

1. В Mission Planner → Config → Full Parameter List:
   - `RSSI_TYPE` → **3**
   - `RSSI_CHANNEL` → **0**
   - Нажмите "Write Params"

2. В ELRS Web UI (приёмник):
   - UART Baud → **420000**
   - Сохранить

3. Перезагрузить автопилот (отключить и подключить питание)

4. Включить аппаратуру и приёмник

5. Проверить в Mission Planner → Status:
   - `rssi` — должен меняться
   - На OSD Walksnail — должны показываться реальные LQ и RSSI

6. **Опционально:** Проверить `ATC_INPUT_TC` — если хотите уменьшить задержку стиков
